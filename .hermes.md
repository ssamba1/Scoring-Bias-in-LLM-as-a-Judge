## Project Identity

This is an LLM-as-a-Judge scoring bias research project measuring how a judge's
sensitivity to nuisance features of a prompt changes with instruction tuning,
across model scales and training paradigms (base vs instruct, SFT vs RLHF).

**A previous version of this project was retracted for fabricated data.** The
evidence is in `DATA_INTEGRITY_AUDIT.md` and the material is quarantined under
`RETRACTED/`. Nothing there is usable, and its conclusions were the *opposite*
of what the honest data show. Do not restore, cite, or reason from it.

## Key Findings (must be correct in all outputs)

These come from `paper/honest/` and are checked against the data by
`paper/honest/repro/check_prose.py`:

- **Bias ↑ after instruction tuning**, for all five bias types. This reverses the
  retracted version's headline claim that format bias decreases.
- **Judges get sharper yet more biased**: answer-distribution entropy falls
  (2.04 → 1.45 bits, 11/13 families) while bias rises. Decisiveness correlates
  *negatively* with bias (ρ=-0.41).
- **Responsiveness is what bias tracks**: it rises 0.14 → 0.26 (12/13 families)
  and correlates +0.82 with bias.
- 13 open-weight families, 26 checkpoints, 0.1–8B, five bias types, 62,940
  scored judgments.

## Workflow Rules

1. **Always run tests before declaring done**  `cd research-draft && python -m pytest tests/ -x -q` or `python tests/run_all.py`
2. **No `print()` in production code**  use logger
3. **Prefer `pathlib.Path`** over `os.path`
4. **Checkpoint early, checkpoint often**  platform path differences WILL bite if you don't
5. **Cost gates**  never spin up a Colab run without checking if a Kaggle T4 run suffices
6. **Verify model IDs and auth** before giving instructions  check HF_TOKEN, provider caps, model availability
7. **Never fabricate results**  if a run failed or didn't produce output, report the failure
8. **Run `make lint` before committing**  catches formatting and style issues
9. **Run `make test` to verify nothing is broken** after any code change
